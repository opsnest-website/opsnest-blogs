# OpsNest Blogs

A reusable, Markdown-powered blog module intended to live in its own repository and be included in the OpsNest website as a Git submodule. Articles are content files; the presentation and behavior are generic and reusable across topics.

## Features

- Markdown articles with YAML-style frontmatter
- Listing cards, article pages, search, category filters, and clickable tags
- Reading-time estimate, author/date metadata, optional updated date
- Draft posts hidden from the published list
- Markdown code blocks, tables, links, lists, and images
- Sanitized rendered Markdown via DOMPurify
- Responsive dark theme designed to complement OpsNest
- Hash-based article URLs so pages work on static hosting without server rewrites
- Relative Vite asset paths for publishing beneath `/blog/`

## Run locally

Requires Node.js 20+.

```bash
npm install
npm run check
npm run dev
```

## Build

```bash
npm run build
npm run preview
```

The static output is written to `dist/`.

## Add an article

1. Copy `content/ARTICLE-TEMPLATE.md` into a category directory, for example `content/devops/my-topic.md`.
2. Fill in the frontmatter fields. `title`, `date`, `category`, `author`, and `tags` are recommended.
3. Set `draft: true` while writing. Change it to `draft: false` or remove the field to publish.
4. Commit and push. The listing is generated from Markdown files at build time.

### Frontmatter fields

| Field | Required | Purpose |
|---|---|---|
| `title` | Yes | Article heading and card title |
| `description` | Recommended | Listing excerpt and page description |
| `slug` | No | URL identifier; defaults to filename |
| `date` | Recommended | Publication date (`YYYY-MM-DD`) |
| `updated` | No | Last updated date |
| `author` | No | Defaults to `OpsNest` |
| `category` | No | Defaults to `General` |
| `tags` | No | YAML list or inline list |
| `cover` | No | Reserved for future card imagery |
| `draft` | No | `true` hides the post |

## Suggested separate repository

Create `https://github.com/opsnest-website/opsnest-blogs.git` and push the contents of this directory to its `main` branch. Then, in the OpsNest website repository:

```bash
git submodule add https://github.com/opsnest-website/opsnest-blogs.git modules/blogs
git add .gitmodules modules/blogs
git commit -m "Add reusable blog module"
git push
```

If the submodule already exists, update its pinned commit instead of running `git submodule add` again.

## GitHub Pages integration

The main website's GitHub Actions workflow should:

1. Check out the website with `submodules: recursive`.
2. Run `npm ci`, `npm run check`, and `npm run build` inside `modules/blogs`.
3. Copy `modules/blogs/dist/` to the main deployment artifact at `dist/blog/`.
4. Deploy the combined static artifact.

Commit a `package-lock.json` generated by `npm install` in this repository before switching the workflow to `npm ci`. Keep the blog module's repository public for unauthenticated submodule checkout, or configure GitHub Actions credentials if it is private.

## Design principle

Keep the blog engine generic. Topic-specific information belongs in article frontmatter and Markdown content, not in React components. This allows DevOps, cloud, security, tutorials, release notes, or personal engineering posts to share one template.
